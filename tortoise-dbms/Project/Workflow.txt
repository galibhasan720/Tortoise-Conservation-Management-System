Part 1: What Does This DBMS Do? (System Architecture)
At its core, your system is a Centralized CRUD Hub (Create, Read, Update, Delete) combined with an Automated Telemetry Pipeline. It replaces scattered paperwork with a single, relational "Source of Truth" to manage wildlife conservation.

Here is exactly how data flows through your system in the real world:

Intake (Create): The Collection Officer rescues a tortoise and uses the system to generate a new TORTOISE_PROFILE. They map the tortoise to specific SPECIES_DICT data to ensure biological accuracy.

Placement (Update): The tortoise is assigned to a specific physical ENCLOSURE.

Daily Operations (Create/Read): * The Caretaker logs daily meals into the FEEDING_LOG.

The Veterinarian reads the profile history and logs new diagnoses into the HEALTH_RECORD.

The Breeding Officer pairs specific male and female IDs to create a BREEDING_RECORD.

Automated Monitoring (Create/Alert): IoT Devices inside the enclosures constantly push temperature and humidity data into the IOT_TELEMETRY table. If conditions become dangerous, the system generates an ALERT for the Environmental Tech to resolve.

Strategic Oversight (Read): The System Administrator / Supervisor does not enter daily data. Instead, they run complex SQL queries (joining profiles, health records, and feeding logs) to view aggregate dashboards, track conservation success rates, and manage the TASK_SCHEDULE for the staff.

Part 2: The Perfect Project Workflow (How to Build It)
To build this application perfectly without encountering dependency errors or broken logic, you must build from the "bottom up"—starting at the database layer and finishing at the user interface.

Here is your exact development roadmap:

Phase 1: The Data Layer (Infrastructure)

Action: Boot up XAMPP, open phpMyAdmin, and execute your schema.sql file.

Result: The database is created, all tables are built in the correct order to respect Foreign Keys, and the dummy data is inserted. The database now enforces all business rules (e.g., you cannot log a feeding for a tortoise that doesn't exist).

Phase 2: The Bridge (Backend Logic)

Action: Write includes/db_connect.php.

Result: You establish a secure, PDO-based connection between your PHP application and the MySQL database.

Phase 3: The Presentation (The "Read" Operation)

Action: Create includes/header.php, includes/footer.php, and index.php.

Result: You build the main dashboard. You write a SELECT query with INNER JOINs to fetch the tortoise data from the database and loop through it to display a clean, Bootstrap-styled HTML table.

Phase 4: Data Entry (The "Create" Operation)

Action: Write create.php.

Result: You build an HTML form. You write PHP logic to query the database for dropdown options (like Enclosures and Species). When the user submits the form, your script securely executes an INSERT INTO query to add a new row to the database.

Phase 5: Data Modification (The "Update" & "Delete" Operations)

Action: Write edit.php and delete.php.

Result: You allow users to modify existing records. edit.php uses an UPDATE query to change data (like moving a tortoise to a new enclosure), and delete.php securely removes records from the system.

Phase 6: Refinement (Advanced DBMS Features for the Viva)

Action: Implement advanced database logic directly in MySQL.

Result: You create SQL VIEWS (virtual tables that combine complex data for easier reading) and TRIGGERS (automated database reactions, like automatically changing a tortoise's status to "Quarantine" if a specific health record is logged).
